# 04. 股票数据分析 SOP

## 1. 接到问题后的第一步

先把问题转换为数据任务，不直接进入计算。

至少确认：

1. 市场和证券类型；
2. 证券代码或样本范围；
3. 起止时间；
4. 日线/分钟线等频率；
5. 复权方式；
6. 时点口径：问题是在历史某日还是当前；
7. 需要的字段和指标；
8. 输出是表格、图、统计还是解释；
9. 是否允许使用缓存；
10. 数据不可用时如何降级。

缺少关键口径时，Agent 应说明采用的最小假设。不能把“看一下走势”自动扩展成交易建议。

## 2. 只读查询 SOP

```text
Step 1: health
  - InStock HTTP 是否 200
  - 生产适配器是否 ok

Step 2: freshness
  - expected_as_of
  - actual_as_of
  - 核心刷新是否成功

Step 3: coverage
  - 必填列是否存在
  - 目标字段覆盖率
  - 样本行数/证券数

Step 4: snapshot
  - 保存原始数据
  - 保存请求与 SHA-256

Step 5: query/compute
  - 只用确定性代码

Step 6: response
  - 状态、日期、来源、结果、限制
```

任何步骤失败都不能跳过继续给确定性结论。

## 3. 单标的分析模板

输入：

```yaml
symbol: "000001"
market: "CN-A"
frequency: "1d"
start: "2025-01-01"
end: "2026-07-21"
adjustment: "qfq"
metrics:
  - return
  - volatility
  - drawdown
  - sma
  - rsi
```

输出顺序：

1. 数据状态和截止日期；
2. 样本行数和缺失；
3. 价格/收益的描述统计；
4. 指标值和计算口径；
5. 异常点或数据限制；
6. 不能从这些数据推出什么。

不输出“必涨”“稳赚”“建议满仓”等结论。

## 4. 横截面分析模板

横截面分析必须避免不同日期和不同字段覆盖混用：

- 所有标的使用相同 `as_of`。
- 明确股票池的生成时间和幸存者偏差。
- 先输出 eligible universe 数量，再输出分析覆盖数量。
- 缺失指标不能默认记为 0。
- 排名只代表指定指标排序，不自动等于投资建议。
- 行业、市值和流动性分布应作为结果背景。

结果至少包含：

```json
{
  "universe_count": 0,
  "eligible_count": 0,
  "analyzed_count": 0,
  "excluded": {
    "missing_required_fields": 0,
    "stale": 0,
    "insufficient_history": 0
  },
  "as_of": "YYYY-MM-DD",
  "metric_definition": {},
  "distribution": {},
  "limitations": []
}
```

## 5. 历史统计/回测最低要求

本仓库不交接具体策略，但任何后续获批的历史评估都必须满足：

- 时间序列拆分，不随机打乱未来和过去。
- 信号只能使用当时已发布的数据。
- 证券池应尽量包含退市/暂停标的，说明幸存者偏差。
- 明确开盘、收盘或下一交易日成交假设。
- 加入手续费、滑点、涨跌停、停牌和成交量约束。
- 参数选择区间与最终评估区间分离。
- 报告总收益、年化、波动、最大回撤、换手、交易次数和分年结果。
- 做样本外和敏感性分析。
- 保存所有参数和输入哈希。

LLM 只解释报告，不能从图形肉眼估算收益或回撤。

## 6. 指标计算

本仓库的指标是数据分析基础件：

```bash
stock-data-agent indicators \
  --input data/processed/daily.csv \
  --output outputs/indicators.csv
```

指标实现要求：

- `groupby(code)` 后按日期排序；
- 滚动窗口不居中；
- 当期指标只使用当期及以前数据；
- 历史不足返回 NaN；
- 测试首个有效位置；
- 数据追加后回归比较历史结果。

## 7. 质量失败时怎么回答

示例：

```text
状态：降级
数据截止：2026-07-16；按交易日历本应达到 2026-07-20
服务：InStock HTTP 正常，但核心刷新失败
结果：只可展示 7 月 16 日历史快照，不能作为今日数据
限制：最新两个交易日缺失；下游提醒已阻断
下一步：修复上游空响应/字段异常，刷新成功后重新计算
```

不要回答“没有符合条件的股票”，因为空结果可能来自数据失败。

## 8. 分析工作区

每个新任务独立：

```text
research/<task>/
├── README.md             问题、口径、数据源、运行方法
├── requirements.txt      固定依赖
├── config.example.yaml   无秘密示例
├── data/raw/             不可变输入
├── data/processed/       标准化数据
├── src/                  获取和计算
├── tests/                单测/断言
├── outputs/              结果
└── validation.json       验证清单
```

`README.md` 至少包含：

- 目标与非目标；
- 数据日期和来源；
- 复权、单位、时区；
- 一键运行命令；
- 输入/输出说明；
- 已知限制；
- 结果不能用于什么。

## 9. 发布前审查

```text
[ ] as_of 与 expected_as_of 已核对
[ ] 数据源和回退源已写明
[ ] 必填字段覆盖通过
[ ] OHLCV 质量通过
[ ] 没有未来数据
[ ] 指标由脚本计算
[ ] 输入和代码版本可追踪
[ ] 结果包含限制
[ ] 没有策略、候选、秘密和收件人标识
[ ] 没有把历史快照写成实时数据
```
